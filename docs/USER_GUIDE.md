# Miner Hearth user guide (v1.17.0)

**Miner Hearth** keeps your home miners tuned, watched and honest about the odds. It auto-tunes **AxeOS** miners (Bitaxe-class, NerdQAxe / NerdOCTAxe) up to **850 MHz** (NerdOCTAxe capped at **800 MHz** normal max unless overclock opt-in is enabled), monitors **Antminer S19** over CGMiner (TCP 4028) with optional **Braiins OS+** power-target management, and shows everything in one dashboard window.

Donate BTC: `bc1q3m8usp6mffv4txhwcltq9lu9jltx02eyukgrvf` (also in the app header with a **Copy** button).

It is pure Python 3 standard library (no pip packages) and ships as a single Windows program, **`MinerHearth.exe`** (installer or portable zip), plus a headless web edition for Linux, Docker, Umbrel and 5tratumOS (see below). Nothing is preset for anyone's machines: `config.json` ships with `"devices": []`, and everything you add lives in `userdata\`, so the folder is safe to share (just don't share `userdata\`).

## Feature overview

| Area | What it does |
| --- | --- |
| **Autotune (AxeOS)** | Frequency steps by temperature, voltage by HW-error tolerance (target 0%, 0.5–1% acceptable, >1% out of tolerance), emergency drop at ASIC ≥ 62.5 °C / VR ≥ 65 °C. Global caps & targets plus per-machine overrides. Capability-based, never by IP or hostname. |
| **Antminer S19** | CGMiner monitoring (hashboards, fans, pools). Optional Braiins OS+ power-target nudging (gRPC `braiins.bos.v1` :50051, REST fallback), default OFF, with a read-only **Test connection**. |
| **Block-found alerts** | Triggers when a share / best-session difficulty ≥ the network difficulty **of the coin that machine mines**. v1.16: two short alerts: **Block Found #height** (payout address from the pool username, worker, the difficulty of the share that found the block (v1.16.1; never the best difficulty, "unknown" when nothing reports it), network difficulty, e.g. 2.35M) and **Block Confirmed #height** only once that coin's own blockchain / explorer shows the block paying your address. The height is left off when it is not known. |
| **Problem alerts** | Machine offline, sharp hashrate drop, switched to fallback pool, no shares for N minutes. Each can be toggled, thresholds are configurable, cooldowns prevent spam. |
| **Notifications** | Dashboard banner, original 8-bit sounds (coin chime, 1-up, level clear, power-up, treasure chest, victory fanfare, alarm) or your own .wav/.mp3, master mute, and a Windows toast. |
| **Power cost & profit** | Electricity rate + currency, cost per machine and fleet, expected sats/day (estimate), BTC price, break-even electricity rate. |
| **Block odds** | Per machine and fleet: chance of a block per day / month / year and expected time to block at current difficulty. v1.9: a separate odds panel per coin (BTC, BCH, BSV, XEC, DGB-SHA256, Fractal), each with that coin's own difficulty. |
| **Coin detection** | Works out which SHA-256 coin each machine mines from its stratum job (block height / network difficulty compared with each chain's tip), the payout-address format and the pool host name. Shows "unknown" when unsure; per-machine manual override in Settings → Coins. |
| **Time-of-use schedule** | Peak windows (days + hours) that lower the Axe frequency cap or the Braiins power-target ceiling. The tuner keeps working inside the limits; emergency protection always wins. |
| **History** | 24 h, 7-day (5-min buckets) and 30-day (30-min buckets) charts per machine or fleet, CSV export. Dashed 24 h average hashrate line with its value on the hashrate chart. |
| **Session best share** | Antminer / Braiins: best share since the miner's last restart next to the all-time best (from the API's since-start value, else derived and reset when uptime drops). Persisted in `userdata\session_best.json`. |
| **Pool health** | Accepted / rejected / stale shares, reject rate, miner-reported ping and ping loss per machine; alert when a pool starts rejecting shares. **Pool comparison** table: accepted/rejected, latency and uptime per pool over 24 h / 7 days. |
| **Ambient / intake temperature** | Shown where the miner reports it (AxeOS ambient keys; Antminer explicit ambient or the coolest board-inlet sensor, labelled as such). |
| **Chip health** | Logs the lowest voltage that ran stable at each frequency per day and flags possible wear when the same frequency needs noticeably more voltage than it used to. |
| **Quiet mode** | Scheduled fan cap for AxeOS machines (e.g. nights); the tuner lowers frequency to stay on target, and emergency temperatures hand the fan straight back to automatic. Off by default. |
| **Maintenance restarts** | Optional weekly restart and auto-restart of a hung miner (hashrate 0 while the API answers, for N minutes). Rate-limited (max per 24 h, minimum gap, 15-min grace). Off by default. |
| **Fleet comparison** | Sortable table: coin, hashrate, J/TH, power, error rate, pool reject rate, chip and ambient temperature, uptime. |
| **Webhooks** | Discord, Telegram and ntfy, with per-alert-type toggles and a **Send test** button. Off by default; URLs/tokens are secrets (hidden from LAN clients, left out of backups unless "Include passwords"). |
| **Appearance & layout** | Dark, light and high-contrast themes; firelit stone-wall dashboard background (v1.17.1, Settings → Appearance → *Dashboard background*, on by default; never in high contrast); a footer with the running version; °C or °F display (all limits and logic stay in °C). Drag-and-drop (or ▲/▼) ordering of card fields, summary-bar items and dashboard sections (e.g. charts above the cards), persisted, with *Reset layout*. |
| **Tuning timeline** | Every frequency / voltage / power-target change with reason, source (autotune, emergency, schedule, manual, braiins) and time; `userdata\tuning_log.jsonl`, rotated at 1 MB × 3. |
| **Network stats** | Block height, difficulty and next difficulty adjustment (% and ETA) in the header. |
| **Phone access** | Opt-in LAN listener (0.0.0.0, your port) with optional PIN and read-only mode. Default stays this-PC-only. Mobile-friendly layout. |
| **Backup / restore** | One JSON file with machines, overrides, visible fields, card order, alerts, sounds and schedules. Passwords excluded unless you tick "Include passwords". |
| **Firmware notices** | Daily check of GitHub releases (bitaxeorg/ESP-Miner, shufps/ESP-Miner-NerdQAxePlus) and the Braiins OS feed; a badge appears when a machine runs older firmware. Silent when offline. |
| **Fault flags & explainers (v1.10)** | Per-card error badge from the miner's own fault flags: AxeOS `overheat_mode`, `power_fault`, `hardware_fault`, `miningPaused`, reset reason; NerdQAxe+ `boardError` / `shutdown` / `lastResetReason`; stock Antminer empty or missing hashboards (`chain_acn`/`chain_acs`) and fans at 0 RPM; Braiins OS+ error codes and status (saved login). Each fault opens a plain-English explainer (meaning, likely cause, first checks, guide link). Codes that are not in the catalog are shown word-for-word as "Unmapped". |
| **Clear / Reset (v1.10)** | Manual button per fault, never automatic: AxeOS clear overheat flag / resume / restart, NerdQAxe+ restart (OTP respected), Braiins OS+ resume or restart (never factory reset), stock Bitmain reboot over HTTP Digest **only** with a web password you saved yourself. Asks first, blocked while hot or offline, rate-limited, dry-run aware, logged. |
| **Fault history, logs, diagnostics (v1.10)** | Timeline of faults appearing / clearing, your resets and auto-restarts (`userdata\fault_history.json`); optional *Hardware fault* webhook (off by default); **Capture log** saves the miner's log (AxeOS, Braiins OS+, stock Bitmain) and explains known lines; **Diagnostics** downloads a redacted JSON bundle for support. |
| **Pool switches & restarts are not faults (v1.15.5)** | When a miner's configured pool changes (from Miner Hearth or on the miner itself), Miner Hearth restarts a miner, or a miner reboots, the alerts that are normal during that process (offline, hashrate drop, no shares, fallback pool, pool rejects, and start-up readings such as a -1 °C sensor or "pool not connected") are paused for up to 10 min and the card shows a blue info note instead. The pause ends as soon as the miner is hashing and getting shares accepted on its primary pool, and the hashrate / share baselines start fresh. Overheating, VR temperature and real hardware faults always alert; a miner that has not recovered when the pause ends gets one alert saying so ("did not recover after the pool switch"). **Pause alerts** on a card silences one machine for planned work. Settings → Pool Switches & Restarts. |
| **Full event log (v1.15.4)** | Append-only, redacted JSON Lines log in `userdata\logs\nk-events-YYYY-MM-DD.jsonl` (earlier days gzip-compressed): every alert raised / recovered / dismissed, fault appearing / clearing / reset, connection loss and recovery with the exact error, exception class, failure count and API latency, miner reboots (uptime going backwards), pool switches / failovers, session-best resets, every tuning / power-target / frequency / voltage change, restarts, time-of-use and quiet windows, firmware checks, settings changes, app start / stop / unclean shutdown, uncaught exceptions with tracebacks, plus a telemetry snapshot of every machine every 5 min and all raw API fields hourly. Kept 14 days / 200 MB by default. **Settings → Full Event Log → Export full log** makes one zip (24 h / 7 days / 30 days / everything) that is safe to send for review. |
| **Live updates (v1.16)** | Off by default. Point Miner Hearth at an update package you trust (a .zip file or an https:// URL you enter); it checks the SHA-256 manifest (and an Ed25519 signature against keys you trust, if you add any) before anything is applied. Coin data, miner plugins and dashboard files reload at once; program files use **Quick restart** (state saved, tuner paused safely, resumed). **Roll back** / **Remove all** at any time. No update server; nothing is downloaded on its own. Packages are made with `tools/make_update.py`. |
| **Saved pools (v1.16.2)** | A library of stratum pools (name, `stratum+tcp://` / `stratum+ssl://` address and port, username with an optional `{worker}` placeholder, password (default `x`, masked, kept on this PC), optional coin auto-detected from the host) in `userdata\saved_pools.json`, so updates and restarts keep it; it ships empty. Add / edit / delete / reorder in **Settings → Saved Pools**, or **Save this pool** from a machine's primary or fallback pool (and each row of an Antminer / Braiins pool list). In a machine's pool editor, pick saved pools for the primary (and fallback, where the firmware allows it) and optionally use the machine's name as the worker. Export / import as JSON. |
| **Node monitoring (v1.17)** | Off by default (**Settings → Node Monitoring**). Watches your own **Bitcoin Core / Knots** node over RPC (sync %, height vs. headers and the network, peers, mempool, size on disk; alerts when it is down, falls behind or has no peers), other coins' nodes with the same RPC (eCash, CHTA, BCH, DigiByte, ...), **LND** / **Core Lightning** (synced to chain, active / inactive / pending channels, peers), **Fulcrum / Electrs** (tip compared with your node or the network), and this computer's **CPU, temperature, memory and disk** (low-disk and temperature alerts). RPC passwords, cookie paths, macaroons and runes stay in `userdata\nodes.json` on the Miner Hearth computer and never reach a browser; nodes can only be added or changed on that computer. Alerts use the usual sounds / notifications / webhooks ("Node alerts"). On Umbrel the Bitcoin and Electrs apps are picked up automatically. |
| **Details panel (v1.10)** | **Details** button on every card: every component reading the machine exposes (chip/ASIC, VR, board, PSU, ambient temps; input/core voltages, current, power; each fan's RPM/%; per-chain chip counts and chip status; frequency, firmware, uptime, reset reason, Wi-Fi RSSI) plus an **All fields** tab listing every other numeric/text field under its API name, with a filter. Read-only, °C/°F and themes respected. |

## Applying a live update (v1.16)

1. Settings → **Live Updates** → tick **Allow live updates** (off by default; only works from this PC, not from a phone on the LAN).
2. Optional but recommended: paste the publisher's public key under **Trusted signing keys** and tick **Only accept packages signed by one of these keys**.
3. Choose the package `.zip` (up to 9 MB in the browser; bigger packages via an `https://` URL), or paste its URL. Paste the SHA-256 the publisher gave you if you have one.
4. **Check package** shows the version, the files, the signature status and whether a restart is needed. Nothing changes yet.
5. **Apply update**. Coin data, plugins and dashboard files work immediately; program-file updates need **Quick restart** (the tuner finishes its step, the state is saved and resumed after about 10 s).
6. **Roll back** returns to the previous update set; **Remove all updates** returns to the shipped version. If an updated program file stops the app from starting twice in a row, it starts without those files automatically.

Publishers: `python tools/make_update.py genkey my-update-key.txt` (prints the public key to share; keep the key file private), then `python tools/make_update.py build <folder> update.zip --version 1.17.1 --min-app 1.17.0 --key my-update-key.txt`. The folder may contain `app/*.py`, `app/nk_adapters/*.py`, `plugins/*.py`, `coins.json`, `ui/*` and `NOTES.md`. Share only the public key.

## Upgrading to v1.17.0 (the program used to have another name)

Up to v1.16.3 this program had a different name; v1.17.0 is the same app under the name **Miner Hearth** (why: [CHANGELOG.md](../CHANGELOG.md)). Your machines, settings, saved pools, history and event logs come with you:

- **Installer:** run `MinerHearth-Setup-v1.17.0.exe`. It installs to `%LOCALAPPDATA%\Programs\Miner Hearth`, closes the old program if it is running (it asks first), removes the old program files, Start Menu / Desktop shortcuts, sign-in entry and its entry in Windows *Apps*, and **keeps the old folder's data** (`userdata\`, `logs\`, `config.json`). On its first start Miner Hearth copies that data into its own folder. Untick *Move from the old name* in the installer to leave the old install alone.
- **Portable zip:** unzip `miner-hearth/` **next to** your old folder (same parent folder; the old folder names it recognises are the old program's install folder and the portable folder names used before), or extract it over the old folder. Start `MinerHearth.exe`; data from the old folder is copied on the first start. Delete the old `.exe` afterwards.
- The copy happens once, only if the new folder has no machines / settings of its own, never overwrites a file and never changes or deletes the old data. What was copied is recorded in `userdata\migration.json` and in the log.
- **Live updates can't make this jump:** an old (v1.16.x) program cannot live-update itself to v1.17.0, because the program file itself changed name. Install v1.17.0 once with the installer or zip; later v1.17.x live updates work as before (old-format update packages are still accepted).
- Old and new can't run at the same time (they share the single-instance lock).

Details for every case: [docs/MIGRATION.md](MIGRATION.md).
